# 路线图：让 PCL 下载修复器长期可用

本文把“继续增强项目”拆成四条线：**正确性、版本韧性、自动化/信任、生态与分发**。
优先级按“用户是否会因此无法使用”排序，而不是按实现难度排序。

## 现状（v1.2）

已完成：

- 五个受限方法的 IL 恢复，支持 PCL 2.99 正式版 413 与快照版 414；
- 412（2.14）等 2.99 之前版本可关闭 PCL 自动更新，停留在当前版本继续使用下载功能，并可精确恢复原设置；
- 修复前后方法语义哈希比对，只允许五个目标方法与一个补全回调变化；
- 程序集身份 + 全部内嵌资源的指纹校验；
- 原子替换、文件属性保留、同一目标写入互斥；
- 原版备份、`.pclfix.json` 还原清单、PCL 更新后的备份自动归档；
- `verify` / `info` / `patch` / `restore` / `selfcheck` 的纯 JSON 输出与稳定退出码；
- xUnit 单元测试、CLI 契约测试、可选真实 PCL 集成测试；
- GitHub Actions CI、标签发布、SHA-256 与构建来源证明。

## P0：正确性（持续）

这些工作直接决定“用户会不会丢文件或修坏 PCL”。

1. **更多真实构建回归**
   - 为每一个新的 PCL 2.99 快照补充集成测试样本（本地/CI 私有样本，不随仓库分发）。
   - 记录每个构建的 SHA-256、方法签名、恢复结果与还原结果。
2. **部分修复的恢复路径**
   - 当前对“部分修复且没有原版备份”的文件会拒绝修复，避免把部分文件当作原版。
   - 下一步提供 `--adopt-backup <path>`：允许用户显式提供正确的原版 EXE，再继续修复。
3. **崩溃恢复**
   - 若进程在“替换目标”与“写清单”之间崩溃，下一次运行应能根据备份哈希恢复清单。
   - 增加启动时的残留临时文件清理（只清理本工具命名模式的文件）。
4. **磁盘/权限边界**
   - 只读目录、网络盘、长路径、符号链接/重解析点、FAT/exFAT 的替换行为测试。
   - 目标文件位于 OneDrive/杀软实时扫描目录时的重试与明确报错。
5. **资源指纹性能**
   - 当前每次修复会多次读取 4 MB 级资源；在低速磁盘上可缓存一次读取结果。

## P1：版本韧性（下一阶段重点）

PCL 更新是最大的外部风险：方法可能改名、签名可能变化、限制方式可能从“删除方法体”变成别的形式。

1. **动态方法发现**
   - 不再只依赖五个固定签名；扫描包含限制文案、或调用已知限制回调的方法。
   - 将发现结果与恢复模板做签名/语义匹配，匹配失败才中止。
   - 输出“发现了哪些受限方法、哪些能恢复、哪些不能”的诊断报告。
2. **恢复模板格式升级**
   - 模板自带方法名、目标签名、源构建哈希与版本；加载时逐项校验，而不是依赖固定顺序。
   - 支持多个模板（按 PCL 大版本/限制变体选择）。
   - 允许从用户提供的限制前 EXE 现场生成模板（`--donor <exe>`），作为官方模板未覆盖时的兜底。
3. **新限制形态**
   - 检测“方法仍在但被常量折叠/提前 return/替换 UI 可见性”等变体。
   - 对无法安全恢复的构建，给出“为什么不能修”的可操作说明，而不是泛化的“不支持”。
4. **PCL 更新感知**
   - 已支持手动关闭 PCL 自动更新（`disable-update`，写入 `PCL\Setup.ini` 的 `SystemSystemUpdate:3`）。
   - `patch --launch`：修复后直接启动 PCL，适合做快捷方式。
   - 可选的 `watch`/托盘模式：检测到 PCL EXE 变化后提示重新修复（默认关闭，避免驻留与误报）。
5. **跨版本状态识别**
   - 用方法结构 + 资源 + 版本综合判断，而不是依赖哈希白名单。
   - 对官方未来恢复下载功能的版本，正确显示“无需修复”。

## P2：自动化与信任

1. **CLI 契约固化**
   - 为 JSON 增加 `schemaVersion` 与字段级兼容性测试；新增字段只增不改。
   - `verify --require-patched`：状态不满足时返回专用退出码，方便启动器脚本。
   - `--log <file>` 与 `--diagnostics <zip>`：一键导出日志、哈希、状态和环境信息。
2. **可复现构建**
   - CI 中构建两次并比较哈希；固定 SDK 版本与 NuGet 锁文件。
   - 发布页同时给出源码提交、构建日志与 SBOM。
3. **代码签名**
   - 使用 Authenticode 证书签名两个 EXE，RFC 3161 时间戳。
   - 向 Microsoft Defender/主流杀软提交误报申诉；发布页说明签名指纹。
   - 在 `selfcheck` 中显示签名者与时间戳状态。
4. **供应链**
   - GitHub Actions 构建来源证明（已接入）；可进一步增加 SLSA level 3 与独立复现构建。
   - 对 `third_party/Mono.Cecil.dll` 与 `resources/RestoreDonor.dll` 做来源与哈希审计。

## P3：生态与分发

1. **安装发现**
   - 自动发现常见目录、开始菜单快捷方式、便携版相邻目录；支持 `PCL_HOME`。
   - 多实例列表：一次扫描多个 PCL，批量 `verify`。
2. **启动器集成**
   - 提供 PowerShell 模块/退出码文档，方便第三方启动器在启动前自动检查并修复。
   - 与 PCL 的“更新后重启”流程配合，减少用户手动操作。
3. **文档与本地化**
   - 英文 README（面向非中文 PCL 用户与海外 fork）。
   - 截图/GIF 演示“检测 → 修复 → 还原 → 更新后再修复”。
   - 常见错误码对照表。
4. **分发**
   - GitHub Releases（已有）、SHA-256（已有）、构建来源证明（已有）。
   - 评估 winget / Scoop 清单；注意 PCL 分发许可与“第三方”标识。
5. **社区**
   - Issue 模板要求附 `verify --json`、工具版本、Windows 版本与日志。
   - 公开“支持矩阵”，让用户知道哪些构建已验证。
   - 贡献指南、行为准则、安全报告流程。

## 明确不做

- 不伪造服务器响应、不修改网络请求、不绕过 Mojang/Microsoft 账号或付费；
- 不注入 PCL 进程、不写启动项、不收集用户信息；
- 不把 PCL 完整程序或图标打包进本工具；
- 不承诺绕过当地法律法规；下载内容的使用责任仍由用户承担。

## 衡量指标

- 新 PCL 构建发布后，工具在多长时间内给出“可修复/不可修复”的明确结论；
- 集成测试覆盖的构建数量；
- 修复/还原失败率与“需要手动删除备份”的支持请求数量；
- 误报投诉数量与签名后的 SmartScreen 表现；
- `--json` 消费者（脚本/启动器）数量与 issue 中的集成案例。
